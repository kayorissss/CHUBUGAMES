# 🍔 CHUBUGAMES

Мини-игры про пацанов. **29 игр, работает без интернета вообще**: прогресс в `localStorage`,
вся графика рисуется на Canvas, звук синтезируется через WebAudio. Один код, три оболочки —
Android (APK), Windows (exe) и PWA в браузере.

## СКАЧАТЬ

| Куда | Что качать | Ссылка |
|---|---|---|
| **Компьютер, обычный способ** | `CHUBUGAMES-<версия>-setup.exe` — устанавливается как программа, обновляется кнопкой внутри | **[СКАЧАТЬ ДЛЯ ПК](https://github.com/kayorissss/CHUBUGAMES/releases/tag/desktop)** |
| **Компьютер, без установки** | `CHUBUGAMES-<версия>-portable.exe` — один файл, можно носить на флешке | **[Portable-версия](https://github.com/kayorissss/CHUBUGAMES/releases/tag/desktop)** |
| **Телефон (Android)** | `CHUBUGAMES.apk` — последняя **подписанная** сборка (тег `latest`) | **[Скачать APK](https://github.com/kayorissss/CHUBUGAMES/releases/tag/latest)** |

Ссылки ведут на страницу релиза, а не на файл напрямую: имя файла содержит версию
(`CHUBUGAMES-1.24.0-setup.exe`, `CHUBUGAMES-1.25.0-setup.exe`, …), и любая прямая ссылка
протухает ровно в момент выхода новой сборки — а такой ссылкой пользуются люди из чужих
инструкций. На странице релиза всегда лежит актуальный файл, а рядом — размер и SHA-256.

Как понять, что сборка свежая, если дата «released this» устарела: дата у релиза
не пересоздаётся (тег `desktop` и тег `latest` — вечные, релиз под ними один), поэтому
в конце описания CI печатает строку `Собрано: <дата UTC> · коммит <sha> · сборка #<номер>`.
Она и есть актуальность; плавающий тег к тому же передвигается на тот коммит, из которого
файл собран, так что «Source code» и «Compare» соответствуют exe. Знак «Latest» на
странице релизов держится за Android-сборку: `latest` — это точка, куда смотрит
встроенная проверка обновлений на телефоне, а не «самое свежее вообще».

**Чем отличаются две версии для ПК?** Игра внутри одинаковая. `setup` ставится в систему,
кладёт ярлык и умеет обновляться сам; `portable` ничего не устанавливает и запускается откуда угодно.
Сохранения у них раздельные. Не уверен — бери `setup`.

Все сборки: [страница релизов](https://github.com/kayorissss/CHUBUGAMES/releases). В описании релиза
публикуются размер и **SHA-256** каждого файла — перед установкой можно сверить, что скачался именно он.

### Первый запуск на ПК: синее окно Windows

Windows покажет **«Система Windows защитила ваш компьютер»**. Нажми **«Подробнее» → «Выполнить в любом случае»**.

Это не признак вируса. SmartScreen считает репутацию по хешу конкретного файла, и у подписанных
платным сертификатом программ она **не переносится между версиями** — каждая новая сборка начинает с нуля.
Поэтому предупреждение появляется на каждом релизе. Убрать его может только платный сертификат
кода подписи, и то не мгновенно.

### Управление на ПК

Полный экран — при запуске, **F11** переключает его в обе стороны. **Esc** — назад, **1–5** — разделы.
Правый клик по плитке игры закрепляет её (на телефоне — долгий тап). Работает полностью офлайн.
Прогресс с телефоном не синхронизируется — переносится файлом сохранения через настройки.

## Дизайн

Ориентир — «шикарное игровое», а не «стеклянное»: интерфейс собирается из **ступенчатых
непрозрачных поверхностей** (фон → карточка → вложенный блок), размытие осталось только у
«геройских» панелей и модалок.

- **Базовые темы три**: чёрный (обсидиан), тёмно-серый (графит), белый. Разница соседних
  поверхностей проверена в L\* (CIE Lab), контраст текста — по WCAG.
- **Акцент выбирается отдельно**: по умолчанию бесплатный «Уголёк» `#FF7A18`, плюс ещё 13 цветов,
  часть покупается за игровые монеты. Акцент красит кнопки, полосы, подсветку и знак приложения.
- **Знак** — векторный бургер из трёх слоёв. Один и тот же файл живёт в интерфейсе
  (`src/ui/Brand.tsx`), в иконках и в заставке (`branding/`, сборка растров — `npm run icons`).
- **ПК** — верхняя панель (знак, разделы, кошелёк) и две зоны на главном экране: плитка мини-игр
  слева, сведения справа; крупность интерфейса подстраивается под ширину окна (или задаётся вручную).
- **Страницы разделов на ПК** — две колонки там, где был длинный столбец (Настройки, Друзья),
  ряды вкладок собраны в компактную панель, читалка фанфиков ограничена по ширине строки,
  сетки карточек пересчитываются от ширины окна. Всё это — utilities
  `.pc-cols`/`.pc-col`, `.pc-tabs-row`, `.pc-reader` в `src/index.css`; на телефоне они
  `display: contents`, то есть раскладка общая и правка карточки приходит в обе оболочки сразу.
- **Телефон** — та же разметка: контейнеры зон на мобильной ширине `display: contents`, поэтому
  блоки идут в обычном порядке. Править вёрстку нужно один раз, она приходит в обе оболочки.

Подробности, правила знака и как перегенерировать иконки — [branding/BRAND.md](branding/BRAND.md).

## Что внутри

- **29 мини-игр** — от «Лёха-бургер» и «Чубкликера» до шахмат, шашек, нардов, бильярда и кроссворда.
  Все портретные, все на Canvas, у части — свои режимы (спринт, марафон, выживание).
- **Мета-игра**: CHUBCOINS и алмазы, уровни с кривой опыта, престиж (+12% монет за цикл),
  дерево навыков из 9 узлов в 3 ветках, сезон на 30 тиров, 44 ачивки четырёх редкостей,
  3 задания в день и лесенка ежедневного входа на 7 дней.
- **Кейсы** с прокруткой и коллекция карточек друзей (+0.4% монет за карточку), 8 скинов героя, 14 цветов интерфейса.
- **15 друзей**: голова рисуется процедурно (кожа, 6 причёсок, 3 брови, 4 бороды, 3 очка, ширина лица),
  в редакторе — имя, прозвище, коронная фраза, редкость и 4 характеристики.
  Можно загрузить реальное фото: оно сжимается в 320×320 и становится головой босса в играх.
- **Боссы по расписанию**: смена каждые N минут, окно события, уведомление заранее.
- **Казино, фанфики с озвучкой, проверка сети** — вторые страницы, доступны из верхней панели на ПК
  и из карточек на главном экране телефона.

## Разработка

```bash
npm install
npm run dev        # http://localhost:5173  (ПК-раскладка — добавить ?pc=1)
npm run build      # → dist/index.html: один файл, 1.32 МБ (468 КБ gzip), офлайн
npm run check:ui   # ~480 проверок вёрстки, локализации, манифеста и сборок
npm run icons      # пересобрать все иконки из branding/*.svg
npx tsc --noEmit   # типы
```

`check:ui` — grep-утверждения по исходникам: он следит и за дизайном (заставка, раскладка ПК,
знак, темы), и за безопасностью сборок. Поэтому при переименовании классов или шагов CI
придётся поправить `scripts/check-ui.mjs` в том же коммите — иначе сборка красная, и это правильно.

Хочешь посмотреть компьютерную версию в браузере — открой `http://localhost:5173/?pc=1`:
раскладка включится принудительно, а всё, что требует настоящей оболочки (обновление из программы,
размер окна), просто не отзовётся.

## Сборка APK

Сборка идёт в GitHub Actions (`.github/workflows/build-apk.yml`) через Capacitor:
`verify` (npm ci → tsc → build → check:ui) → `build` (debug для веток, release для тегов) →
публикация в релиз `latest` **только** из тега `v*` или ручного запуска с `publish=true`.

1. Вкладка **Actions** → последний прогон *Build CHUBUGAMES APK*
2. Артефакт **CHUBUGAMES-APK** → внутри `CHUBUGAMES.apk`
3. Закинуть на телефон и установить (разрешить установку из неизвестных источников)

Воркфлоу фиксирует портретную ориентацию и оставляет **INTERNET** — разрешение нужно, чтобы
приложение могло проверить релизы и скачать обновление (сама игра работает офлайн).

### Как выпустить релиз

Релизы публикуются **только из тега** — это не бюрократия, а защита: прогон из ветки
не имеет права ничего менять в том, что скачивают люди. Полный путь такой:

1. Поднять версию в `src/core/version.ts` (константа `APP_VERSION`) и в `package.json` —
   они обязаны совпадать, это проверяет `npm run check:ui`.
2. Собрать и проверить локально: `npm run build && npm run check:ui`.
3. Закоммитить и запушить ветку — CI сначала прогонит `verify` (tsc, сборка, проверки
   вёрстки), потом соберёт APK и EXE как артефакты, **релиз не тронет**.
4. Поставить тег с тем же номером: `git tag -a v1.25.0 -m "…" && git push origin v1.25.0`.
   Номер сверяется с `APP_VERSION` («Tag matches the app version») — разошлось, упало.
5. Из тега запускаются обе workflow и каждая в режиме релиза:
   * APK — `assembleRelease` с постоянным ключом, `apksigner verify`, файлы
     `CHUBUGAMES.apk` + `CHUBUGAMES.apk.sha256` в тег `latest`;
   * EXE — `electron-builder`, `checksums.sha256` в тег `desktop`.
6. Старые файлы той же линейки удаляются **после** загрузки новых: если публикация
   упадёт, релиз останется с предыдущими файлами, а не пустым (ссылка не станет 404).
7. Тело релиза начинается со строки `version: <номер>` — именно её читает встроенная
   проверка обновлений, поэтому тело генерируется CI, а не пишется руками.

Если секреты подписи не заданы, шаг настройки подписи останавливает сборку APK —
и это правильно: debug-подписанный файл в `latest` означал бы «конфликт пакетов» у
всех, у кого игра уже установлена. Значения и порядок — ниже.

### Подпись релизов

Ключ подписи **не лежит в репозитории**: `.p12` убран из git, а в CI попадают ключ и пароли
из **Secrets** (`CHUB_KEYSTORE_B64`, `CHUB_KEYSTORE_PASSWORD`, `CHUB_KEY_ALIAS`, `CHUB_KEY_PASSWORD`).
Без них релизный APK не публикуется — ветки собираются неподписанными.
Как выпустить ключ, что именно куда вставлять и почему ротация ключа возможна только с новым
`applicationId` — [android-signing/README.md](android-signing/README.md).

Обновления проверяются до установки: и размер, и SHA-256 файла; качать разрешено только по https
и только с доменов GitHub. Механика — в `src/core/updater.ts` (телефон) и `desktop/main.cjs` (ПК).
