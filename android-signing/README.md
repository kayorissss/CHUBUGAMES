# Подпись APK — как это устроено

## Почему ключа нет в репозитории

Раньше `chubgames.p12` лежал здесь, в git, и пароль к нему тоже был виден
в `scripts/setup-android-signing.mjs`. Репозиторий публичный, значит:

1. любой мог взять ключ и выпустить **свой** APK с **нашей** подписью —
   Android принял бы его как обновление и поставил поверх настоящего;
2. ключ нельзя было заменить: новый ключ = «конфликт подписи» у всех,
   кто уже установил игру (пришлось бы удалять приложение и терялся прогресс).

Ключ из git удалён. Теперь он живёт **только** в двух местах: у автора на
диске и в GitHub Secrets. Файл `android-signing/chubgames.p12` игнорируется
`.gitignore` — случайно закоммитить его нельзя.

## Где что лежит

| Где | Что |
|---|---|
| `android-signing/chubgames.p12` | локальная копия ключа (не в git) |
| Secrets `CHUB_KEYSTORE_B64` | тот же файл, base64 одной строкой |
| Secrets `CHUB_KEYSTORE_PASSWORD` | пароль к хранилищу |
| Secrets `CHUB_KEY_ALIAS` | алиас ключа (обычно `chubgames`) |
| Secrets `CHUB_KEY_PASSWORD` | пароль ключа (часто совпадает с паролем хранилища) |

CI берёт их в `.github/workflows/build-apk.yml`, шаг
`Подпись релиза`. Без секретов сборка всё равно проходит, но **незаметно**
для пользователя остаётся неподписанной — такой APK не публикуется в Releases,
а уезжает только артефактом (см. `Allow unsigned build` ниже).

## Новый ключ (первый запуск или ротация)

```bash
node scripts/make-release-key.mjs
```

Скрипт сгенерирует хранилище с криптостойким паролем, положит его сюда и
распечатает ровно те строки, которые надо вставить в Secrets:

```bash
gh secret set CHUB_KEYSTORE_B64       < /tmp/keystore.b64
gh secret set CHUB_KEYSTORE_PASSWORD  <<< '…из вывода скрипта…'
gh secret set CHUB_KEY_ALIAS          <<< 'chubgames'
gh secret set CHUB_KEY_PASSWORD       <<< '…тот же пароль…'
```

Нужен `keytool` из JDK 17+. Флаг `--days` по умолчанию 10950 (30 лет):
срок действия сертификата важнее «свежести» — просроченный ключ блокирует
обновления, а продлить его задним числом нельзя.

### Ротация ключа — только с новым `appId`

Android сверяет подпись при установке поверх. Сменили ключ, оставив
`com.chubgames.app`, — все существующие пользователи получат «Пакет не
совместим». Поэтому ключ меняют вместе с `appId` в `capacitor.config.json`
(и тогда это фактически новое приложение: прогресс с прошлого не переносится,
кроме файла сохранения через «Настройки → Экспорт»).

## Проверка готового файла

```bash
# отпечаток: должен совпасть с прошлыми релизами
keytool -printcert -jarfile CHUBGAMES.apk

# что хранилище вообще читается паролем из Secrets
openssl pkcs12 -in android-signing/chubgames.p12 -info -nokeys -passin pass:'ПАРОЛЬ'
```

Если `keytool -printcert` показывает `Android DebugKey` — подпись в CI не
применилась (секретов нет или они криво перенесены), в релиз такой файл
класть нельзя.
